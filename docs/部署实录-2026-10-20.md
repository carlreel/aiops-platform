# 部署实录：从零到跑通（2026-10-20）

> 本文档记录**一台全新 Windows 机器从零开始部署本平台的完整过程**，包含每一步的命令、
> 验证方法，以及实际踩到的 6 个坑。
> 用途：换机器 / 重装系统 / 交付给他人时，照着这 一份就能重建。
>
> 环境：Windows 11 家庭版 (26200) / Ryzen 9 8940HX / 15.2GB 内存 / RTX 5060 Laptop 8GB
> 结果：`http://localhost:8000/docs` 可访问，`/health` 返回 `db=up ollama=up`

---

## 零、这个项目是干什么的

一套**可在内网/离线环境交付的私有化 AI 知识库平台**。解决的是这类问题：

> 单位有一堆内部文档（制度、手册、规程），想用大模型问答，
> 但数据不能出内网、不能调公有云 API、机器也上不了外网。

系统组成（全部单机、Docker Compose 编排）：

| 组件 | 作用 | 端口 |
|---|---|---|
| `Ollama`（Windows 宿主） | 跑本地大模型，用 GPU 推理 | 11434 |
| `pgvector` | PostgreSQL + 向量扩展，存切片和向量 | 5432 |
| `rag-api` | FastAPI 写的检索问答服务 | 8000 |
| `prometheus` | 指标采集（可选） | 9090 |
| `grafana` | 监控大盘（可选） | 3000 |
| `node-exporter` / `cadvisor` | 主机 / 容器指标（可选） | 9100 / 8080 |

**检索链路**：
文档 → 切片(512/64) → bge-m3 向量化(1024维) → pgvector 向量召回 + 关键词召回
→ RRF 融合 → top5 → 拼引用提示词 → qwen2.5:3b 生成 → 返回答案 + 出处

## 三、部署步骤

### 阶段 1｜安装 Ollama 并拉模型（约 25 分钟）

#### 1.1 下载

官方地址 `https://ollama.com/download/OllamaSetup.exe`，但它会 307 跳转到 **GitHub Releases**。
国内 GitHub 不通时需要代理，或用 `ghproxy.net`（实测只有 175KB/s，1.48GB 要 1 小时，不建议）。

> 安装包实际大小 **1.48GB**（内置 CUDA 运行库），不是老教程说的 700MB。

验证文件真伪（比 SHA256 更直接）：

```powershell
Get-AuthenticodeSignature "C:\Users\<你>\Downloads\OllamaSetup.exe"
# 期望：Status = Valid，签名者 CN=Ollama Inc.
```

#### 1.2 安装并设置监听地址（★ 关键）

双击安装，一路默认。装完**必须**设这个环境变量，否则容器连不上：

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_HOST","0.0.0.0:11434","User")
```

然后**重启 Ollama**（托盘退出再启动，或重启电脑）才生效。

验证监听地址：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 11434 | Select LocalAddress
# 期望看到 :: 或 0.0.0.0（不能只有 127.0.0.1）
```

#### 1.3 拉模型

```powershell
$ol = "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe"
& $ol pull bge-m3        # 1.2GB 向量化，1024 维
& $ol pull qwen2.5:3b    # 1.9GB 生成
```

> 🔴 **绝对不要用 `qwen3:4b`**。它的 chat template 在最后一条 user 消息后**硬编码 `<think>`**，
> `think=false` 无效，`num_predict` 全被思考过程吃光，`response` 返回**空字符串但 HTTP 是 200**。
> 详见 `docs/故障演练记录.md` 的「演练 0」。

#### 1.4 验证 GPU 生效

```powershell
& $ol ps
# 期望：PROCESSOR 列显示 100% GPU
nvidia-smi --query-gpu=memory.used,memory.total --format=csv
# 期望：约 2600 MiB / 8151 MiB
```

### 阶段 2｜安装 WSL2 + Ubuntu（约 15 分钟）

#### 2.1 首选方式

管理员 PowerShell：

```powershell
wsl --install -d Ubuntu-24.04
```

重启后自动弹 Ubuntu 窗口，设用户名密码（用户名用**小写英文**）。

#### 2.2 如果卡在 Microsoft Store（国内常见）

`wsl --install` 可能只装上 WSL 主干、发行版下不来。**判断方法**：

```powershell
Get-ChildItem "HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss"
# 没有输出 = 发行版没装上
Get-AppxPackage *WindowsSubsystemForLinux* | Select Name,Version,Status
# 有输出且 Status=Ok = WSL 主干装好了
```

**绕过 Store 用 rootfs 导入**：

```bash
# 1) 下载官方 rootfs（约 340MB，国内可达，实测 2.7~8 MB/s）
# https://cloud-images.ubuntu.com/wsl/releases/noble/current/ubuntu-noble-wsl-amd64-wsl.rootfs.tar.gz
# 2) 校验（官方 SHA256SUMS 里取）
```

```powershell
# 3) 先建父目录！wsl --import 只创建最后一级，不创建父目录
New-Item -ItemType Directory -Path "C:\WSL" -Force
# 4) 导入
wsl --import Ubuntu-24.04 C:\WSL\Ubuntu "C:\Users\<你>\Downloads\ubuntu-noble-wsl-amd64-wsl.rootfs.tar.gz"
# 5) 验证
wsl -l -v
# 期望：* Ubuntu-24.04  Stopped  2
```

> ⚠️ import 出来的默认用户是 **root**，不是普通用户。

#### 2.3 内存上限配置

新建 `C:\Users\<你>\.wslconfig`：

```ini
[wsl2]
memory=8GB
processors=8
swap=4GB
localhostForwarding=true
```

> 🔴 **注释必须用纯 ASCII 英文**。WSL 按字节解析 ini，中文注释（3 字节/字）会让 key 错位，
> 报 `键"10"未知` 这类莫名其妙的错误。
>
> 🔴 **`autoMemoryReclaim` 在 WSL 3.0.3 上不被识别**，写了会一直报错，删掉。

### 阶段 3｜在 Ubuntu 里装 Docker（约 10 分钟）

```bash
# 换阿里云源
sed -i 's|http://archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' \
  /etc/apt/sources.list.d/ubuntu.sources
sed -i 's|http://security.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' \
  /etc/apt/sources.list.d/ubuntu.sources
```

**★★★ 强制 apt 走 IPv4（这一步不做，apt 会卡死）**

```bash
cat > /etc/apt/apt.conf.d/99force-ipv4 <<'EOF'
Acquire::ForceIPv4 "true";
Acquire::http::Timeout "20";
Acquire::https::Timeout "20";
Acquire::Retries "2";
EOF
```

> **为什么**：Ubuntu 24.04 的 apt 默认先试 IPv6，而 WSL2 里 IPv6 不通，
> 于是每个源都要先等一遍超时。表现就是 `apt-get update` 停在原地不动好几分钟。
> 加了 ForceIPv4 之后同样的操作 **5 秒完成**。

```bash
# 装 Docker（用阿里云 docker-ce 源）
apt-get update
apt-get install -y ca-certificates curl gnupg
install -m 0755 -d /etc/apt/keyrings
curl -fsSL --ipv4 https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
CODENAME=$(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
https://mirrors.aliyun.com/docker-ce/linux/ubuntu ${CODENAME} stable" \
  > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

systemctl enable --now docker
docker --version && docker compose version
```

#### 3.1 配镜像加速器（不然拉不动 Docker Hub）

```bash
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
EOF
systemctl restart docker
```

> 2026-10 实测：`docker.m.daocloud.io` / `docker.1ms.run` / `docker.xuanyuan.me` 可用
> （`/v2/` 返回 401 属正常，是 Registry v2 的鉴权响应）。
> `dockerproxy.net` 已失效。

### 阶段 4｜部署项目（约 10 分钟）

#### 4.1 代码必须放在 WSL 内部，不能留在 /mnt/c

```bash
mkdir -p /opt
cp -r /mnt/c/Users/<你>/WorkBuddy/.../aiops-platform /opt/aiops-platform
chmod +x /opt/aiops-platform/scripts/*.sh
cd /opt/aiops-platform
```

> **为什么**：`/mnt/c` 走 9p 协议，`docker build`、`pip`、`git` 在那边会慢 5~10 倍。

#### 4.2 生成 .env

```bash
cp .env.example .env
```

关键配置（`.env.example` 里已有默认值）：

```ini
OLLAMA_BASE_URL=http://host.docker.internal:11434
LLM_MODEL=qwen2.5:3b
EMB_MODEL=bge-m3
CHUNK_SIZE=512
CHUNK_OVERLAP=64
TOP_K=5
```

#### 4.3 启动（★ 只起业务，不要一次起全部）

```bash
docker compose up -d pgvector rag-api
docker compose ps
```

> ⚠️ **不要直接 `docker compose up -d`**。那会把 5 个服务全拉一遍，
> 而 `cadvisor` 用的是 `gcr.io/cadvisor/cadvisor`，**`registry-mirrors` 不加速 gcr.io**，
> 必然失败并中断整个 up。
>
> 正确做法：先起业务，监控单独起（见阶段 6）。

#### 4.4 首次构建说明

`rag-api` 是本地构建，Dockerfile 里已配清华 PyPI 源：

```dockerfile
RUN pip install --no-cache-dir -r requirements.txt \
    -i https://pypi.tuna.tsinghua.edu.cn/simple \
    --trusted-host pypi.tuna.tsinghua.edu.cn
```

实测构建耗时 **101 秒**（其中 pip 88.7 秒）。

### 阶段 5｜打通网络（★ 最容易卡住的地方）

#### 5.1 坑一：容器里的 host.docker.internal 指向错的 IP

**现象**：`/health` 返回 `{"db":"up","ollama":"down","ollama_error":"[Errno 111] Connection refused"}`

**诊断**：

```bash
# WSL 能否访问 Windows 的 Ollama
GW=$(ip route show default | awk '{print $3}')
curl -s -m 6 -o /dev/null -w "HTTP %{http_code}\n" http://$GW:11434/api/tags
# 200 = WSL 到 Windows 没问题

# 容器里 hosts 写的是什么
docker exec aiops-rag-api cat /etc/hosts | grep host
# 实测输出：172.17.0.1  host.docker.internal   ← 错！
```

**根因**：`extra_hosts: host.docker.internal:host-gateway` 在 **WSL2 下被解析成 `172.17.0.1`**
（docker0 网桥自己），而不是 Windows 主机的 `172.20.80.1`。

**判断技巧**：`Connection refused` 说明**连到了错的 IP**（对面明确拒绝）；
如果是防火墙拦，会表现为 `timeout`（石沉大海）。**这两个错误要分开想。**

**修复**（改成显式 IP）：

```bash
GW=$(ip route show default | awk '{print $3}')
sed -i "s|^OLLAMA_BASE_URL=.*|OLLAMA_BASE_URL=http://$GW:11434|" .env
sed -i "s|host.docker.internal:host-gateway|host.docker.internal:$GW|" docker-compose.yml
docker compose up -d --force-recreate rag-api
```

> `--force-recreate` 是必须的：环境变量改了，`restart` 不会重新注入。

#### 5.2 坑二：WSL 的 localhostForwarding 对 Docker 端口无效

**现象**：WSL 内部 `curl localhost:8000/health` 正常，但 **Windows 侧 8000 端口零监听**。

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8000   # 没有输出
```

**根因**：Docker 用 iptables 做 NAT 端口映射，不属于"某进程监听"，WSL 的端口代理抓不到。

**修复**：用 Windows 系统级 portproxy

```powershell
$ip = (wsl -d Ubuntu-24.04 -u root hostname -I).Trim().Split()[0]
netsh interface portproxy delete v4tov4 listenport=8000 listenaddress=127.0.0.1 2>$null
netsh interface portproxy add v4tov4 listenport=8000 listenaddress=127.0.0.1 connectport=8000 connectaddress=$ip
```

#### 5.3 坑三：WSL 会随最后一个会话退出而关机

**现象**：命令跑完时 `/health` 是好的，几十秒后再访问就 `无法连接到远程服务器`。

**诊断**：

```powershell
Get-Process vmmemWSL, wslrelay -ErrorAction SilentlyContinue
# 没有输出 = WSL 虚拟机已经关了
```

**根因**：最后一个 `wsl.exe` 客户端退出后约 **8 秒**，WSL 的 VM 自动关机，
里面的 Docker 和容器全部停止。portproxy 规则还在注册表里，但目标 IP 已经不存在。

**修复**：起一个不退出的 WSL 会话

```powershell
Start-Process wsl.exe -ArgumentList "-d","Ubuntu-24.04","-u","root","-e","sleep","infinity" -WindowStyle Hidden
```

停止时用 `wsl --shutdown`。

#### 5.4 一键启动脚本

把上面三件事固化到 `C:\WSL\start.ps1`（管理员运行）：

```powershell
# 1) 让 WSL 常驻
$wslClients = @(Get-Process wsl -ErrorAction SilentlyContinue)
if ($wslClients.Count -eq 0) {
    Start-Process wsl.exe -ArgumentList "-d","Ubuntu-24.04","-u","root","-e","sleep","infinity" -WindowStyle Hidden
    Start-Sleep -Seconds 3
}
# 2) 起容器
wsl -d Ubuntu-24.04 -u root bash -c "cd /opt/aiops-platform && docker compose up -d pgvector rag-api"
Start-Sleep -Seconds 10
# 3) 端口转发（IP 每次重启可能变，所以每次重新探测）
$ip = (wsl -d Ubuntu-24.04 -u root hostname -I).Trim().Split()[0]
netsh interface portproxy delete v4tov4 listenport=8000 listenaddress=127.0.0.1 2>$null | Out-Null
netsh interface portproxy add v4tov4 listenport=8000 listenaddress=127.0.0.1 connectport=8000 connectaddress=$ip | Out-Null
# 4) 健康检查
Invoke-RestMethod http://127.0.0.1:8000/health
```

**日常使用**：演示前跑 `powershell -ExecutionPolicy Bypass -File C:\WSL\start.ps1`，
结束后 `wsl --shutdown`。

## 四、今天踩到的 6 个坑（速查表）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | `apt-get update` 卡住不动好几分钟 | Ubuntu 24.04 先试 IPv6，WSL2 的 IPv6 不通，逐源等超时 | `/etc/apt/apt.conf.d/99force-ipv4` 强制 IPv4 |
| 2 | `wsl --import` 报 `Wsl/ERROR_PATH_NOT_FOUND` | `C:\WSL` 父目录不存在，import 只创建最后一级 | 先 `New-Item C:\WSL` |
| 3 | `.wslconfig` 报 `键"10"未知` | 中文注释让按字节解析的 ini 错位；`autoMemoryReclaim` 不被 WSL 3.0.3 识别 | 注释改纯英文；删掉 autoMemoryReclaim |
| 4 | `/health` 里 `ollama: down`，报 `Connection refused` | `host-gateway` 在 WSL2 解析成 `172.17.0.1`，不是 Windows 主机 | `.env` 写显式 IP，`--force-recreate` |
| 5 | Windows 访问 `localhost:8000` 不通 | WSL 的 localhostForwarding 抓不到 Docker 的 NAT 端口 | `netsh interface portproxy` |
| 6 | 服务活不过 8 秒 | 最后一个 wsl 会话退出后 VM 自动关机 | `sleep infinity` 常驻 + `start.ps1` |

外加一个**代码级 bug**：

| 现象 | 根因 | 解决 |
|---|---|---|
| PowerShell/Postman 里中文全乱码 | 响应头 `content-type: application/json` 缺 `charset=utf-8`，部分客户端按 ISO-8859-1 解码 | 加 `@app.middleware("http")` 统一补 charset |

## 六、已知限制（面试时应主动说明）

1. **单机部署，无高可用**。生产环境需要多副本 + 负载均衡。
2. **3B 模型数值推理能力弱**。实测中它把"80% 清理 / 90% 扩容"两个阈值串了，
   属于「召回正确但生成失真」。生产应换 7B+ 或做更严格的 prompt 约束。
3. **语料仅 3 篇**，只验证了功能通路，不代表真实检索质量。
   生产需 100+ 文档 + 30~50 条评测集。
4. **未接 cross-encoder 重排序**，目前只用 RRF 融合。
5. **cadvisor 未部署**（gcr.io 在国内拉不动），容器指标暂时缺失；
   可选替代：Docker Hub 的 `google/cadvisor`，或启用 Docker daemon 的 metrics 端点。
6. **端口转发依赖脚本**，WSL 重启后需重跑 `start.ps1`。
